- (technique) started Mind Mapping
- (direction by user) no external integrations/network calls — all data and computation stays fully on-device
- (idea by user) Choose Your Own Adventure — branching text-based narrative game
- (idea by coach) CYOA direction split: (a) hand-authored branching story tree as local JSON with multiple endings, vs (b) procedurally-remixed CYOA shuffling scenes/choices from local content pools for replay value
- (idea by user) Combine content-remix CYOA engine with a time-travel theme/context
- (idea by coach) Two time-travel flavors: (a) time-loop — short scenario resets/remixes each attempt, Groundhog-Day style; (b) time-tourist — same locations revisited across eras, choices ripple across eras
- (idea by user) Many-worlds branching: player choices fork new realities; character gets stranded in a branch and must find their way back home
- (idea by coach) Anchor Points mechanic: a few home-reality details (name, object, relationship) that must be restored; choices preserve or corrupt anchors, giving lightweight feedback on how close/far from home you are
- (idea by user) The farther the player deviates from home, the more absurd the branch reality becomes
- (idea by coach) Deviation meter (0-100, shown only through flavor text) gates which local content pools the remix engine draws from: low deviation = mundane scene/choice variants, high deviation = surreal/absurd ones. Doubles as difficulty curve and replay-variety engine
- (idea by user) Design philosophy: obvious 'safe' choices should sometimes still branch anyway ('one step forward, two steps back') so the player can't reliably game their way home quickly, extending playtime
- (idea by coach) 'Safe-looking' choices have a hidden success chance (60-80%) rather than a guarantee; player earns a scarce local resource ('certainty') through anchor-preserving choices, spendable to force a safe outcome when it matters
- (direction by user) Explore visual style branch next, staying within constraints (on-device only, low-barrier first project, no art/design background implied)
- (idea by coach) Typography-and-color-driven visual style: native SwiftUI system fonts + SF Symbols only, no custom illustration assets; deviation meter drives a single accent-color/theme shift from calm desaturated (home) to saturated/high-contrast/glitchy (high deviation), making visual style double as the feedback mechanism
- (idea by user) Include some custom art assets, roughly one illustration per branch-reality experience/scene
- (idea by coach) Two art-scoping shapes: (a) small reusable 'archetype scene' library (8-12 illustrations) recolored/filtered by deviation theme system and reused across the tree; (b) one unique illustration per distinct branch-reality flavor (~10-15), scaling with story design not node count
- (decision by user) Art shape: one unique illustration per distinct branch-reality flavor (~10-15 total), not per node
- (decision by user) Art production plan: generative AI image tools at dev-time (user describes scenes, no personal drawing skill needed); images are pre-generated and bundled into the app, not fetched at runtime
- (idea by user) Ending taxonomy: 1-2 'stay' endings where the player chooses to remain in the branch timeline; 2-4 'return home' endings; the rest end in limbo, stuck in a timeline they don't like
- (idea by coach) Wire ending taxonomy to existing mechanics: 'home' endings = all Anchor Points restored before certainty runs out; 'stay' endings = player deliberately chooses at a late branch to let anchors go; 'limbo' = everything else (partial restoration or certainty exhausted with anchors still broken)
- (idea by user) Deviation meter maxing out is a hard fail. Additionally, there should be scattered hard-fail choices along the tree — obviously bad choices given the circumstance end the run immediately
- (idea by coach) Hard-fail choice tone options: (a) fair/telegraphed — danger is genuinely signaled, failure feels earned; (b) absurd gotcha — deliberately unfair for dark comedy, consistent with escalating absurdity theme
- (decision by user) Hard-fail choices lean comedic-gotcha (absurd, dark humor), not fair/telegraphed
- (technique) started Job to Be Done
- (insight by user) Primary job the project is hired for: get all the way through App Store submission, and learn what it actually takes to build an iOS app
- (idea by coach) Scope-vs-job tension: (a) build full concept (deviation meter, anchors, certainty, remix engine) as v1, more implementation risk before first submission; (b) ship a lean, more linear MVP CYOA first to reach submission fast, treat richer mechanics as a v1.1 update — also teaches the update-shipping pipeline
- (decision by user) Scope decision: lean, more linear MVP CYOA first to reach App Store submission fast; richer mechanics (deviation meter, anchors, certainty resource) deferred to a v1.1 update
- (insight by user) Player-side job: see how their choices affect the story; the story needs to be compelling enough to keep them going
- (idea by coach) Minimal 'choice echo' mechanic belongs in the lean MVP itself (not deferred to v1.1): later scenes reference an earlier pick by name/detail via a few conditional text branches, cheaply delivering the core 'my choices matter' promise
- (decision by user) 'Choice echo' mechanic stays in v1 (not deferred)
- (technique) started One Feature Only
- (decision by user) One Feature Only pick: branching choices with real consequence (choice echo) is the single capability that survives if everything else is cut
- (idea by coach) Make the one feature unbelievably good: (1) let a choice's consequence resurface 2-3 times across the tree instead of a single callback, building a felt thread; (2) an end-of-run 'memory' screen listing the choices made and what they actually caused
- (idea by user) End-of-run memory screen includes a score based on how closely the player stayed to the 'ideal' (home-bound) path
- (idea by coach) Lightweight v1 version: each choice tagged with a small +/- alignment value at write-time, summed silently through play, only surfaced as a score/tier on the end memory screen — no live meter or theming system pulled forward from v1.1
- (technique) started Pirate Code Brainstorm
- (idea by user) Steal: an earnable 'undo choice' feature — rewind to the last choice and pick differently; limited to one use per branch reality
- (idea by user) Undo/rewind credit is earned by accumulating enough 'ideal path' alignment points (reuses the alignment-scoring system from the memory screen); eventually could also be offered as an in-app purchase addon
- (decision by user) Rewind credit stays as compensation for the non-guaranteed 'safe' choices. Design principle: there should always be an ideal path through the story, even if it isn't obvious to the player
- (decision by user) MoSCoW for v1: Must = ending taxonomy (home/stay/limbo, re-wired off alignment score/tier), comedic hard-fail choices, 'safe choice unreliable' pushback (token version, no spendable resource needed). Should = (none remaining). Could = (none remaining). Won't-this-time = undo/rewind credit, IAP addon for rewind credits
- (insight by user) Main concern: creating a compelling enough story to keep the audience engaged
- (idea by user) Later feature (post-v1, breaks on-device-only deliberately): send anonymized play metadata to a self-maintained endpoint to understand player engagement
- (insight) Synthesis: v1's Must-have set (choice echo, alignment score, ending taxonomy) is unified by one throughline — making the story visibly respond to the player — which directly answers the user's core concern (a compelling, engaging story). Telemetry-for-engagement is a natural v1.1+ milestone: validate compellingness informally first (self + friends playtesting) on the small v1 story, then add a maintained analytics endpoint later as a second deliberate revisit of the on-device-only constraint, paired with a second real iOS skill (networking, backend, App Store privacy disclosure).
