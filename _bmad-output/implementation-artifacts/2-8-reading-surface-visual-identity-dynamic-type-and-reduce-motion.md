# Story 2.8: Reading Surface Visual Identity, Dynamic Type & Reduce Motion

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a player, including one using accessibility features,
I want the reading surface to follow the app's visual identity and remain fully usable under Dynamic Type and Reduce Motion,
so that the core experience is accessible end-to-end.

## Scope decision (RESOLVED, read before starting)

epics.md's AC #1 names exactly five components as this story's remaining-token scope: **frame, choice-card, echo-callback, interstitial, continue-button**. Two other things live in the same reading surface but are handled differently:

- **Run-options button** — not in epics.md's AC #1 list, but Stories 2.6/2.7's own code comments explicitly deferred its real `trace-brass`/`ink-primary` palette to "Story 2.8's full DESIGN.md palette pass for every Epic 2 reading-surface component at once" (`RunOptionsButton.swift:28-32`, `FrameView.swift:8-13`, `BranchArrivalInterstitialView.swift:17-22` — the same sentence appears three times). Per project-context.md's doc-conflict rule ("most recent explicit decision wins"), those in-code deferrals win over epics.md's non-exhaustive parenthetical list — **run-options-button's color pass is in scope.**
- **Eyebrow tag** (`{components.eyebrow-tag}`) — AC #4 references a VoiceOver order that names "eyebrow" first, but no eyebrow tag exists anywhere in the codebase, `StoryNode` (`Content/StoryNode.swift`) has no chapter/location field to source its text from, and epics.md's AC #1 doesn't list it as a remaining token. Building it would mean inventing new authored content and extending `StoryNode`'s cases — a content-model change (AD-1), not a visual-identity pass. **Out of scope for this story.** AC #4 below is scoped to the traversal order among elements that actually exist today: prose → choices → run-options-last (already partly done via `.accessibilitySortPriority(-1)` on `RunOptionsButton`, Story 2.7). Flag eyebrow-tag as a real gap for the PM/next story, not something to build implicitly here.
- **"Pager" in AC #4** — there is no visible pager element (page-turn is gesture/tap-zone/VoiceOver-custom-action only, per AD-5). Read "→ pager" as "→ the pager-equivalent accessibility actions" (`storyChoice.pager.nextPage`/`.previousPage`, already implemented on `readingComposition`), not a new visible control.

## Acceptance Criteria

1. **Given** the remaining DESIGN.md tokens for reading surfaces (frame, choice-card, echo-callback, interstitial, continue-button — plus run-options-button, per the Scope Decision above)
   **When** applied
   **Then** all Epic 2 screens render per DESIGN.md with verified WCAG AA contrast (NFR7, UX-DR15) — every color reference in `FrameView`, `ChoiceCardView`, `StoryChoiceView`'s echo-callback block, `BranchArrivalInterstitialView`, the Continue button, and `RunOptionsButton` uses a real DESIGN.md-matching `Color` asset, not a placeholder reuse of an unrelated token (see Dev Notes for the exact placeholder → real mapping per file).

2. **Given** Dynamic Type set to an accessibility size
   **When** reading content or a choice-node's decision point renders
   **Then** content scrolls inside the fixed frame (frame itself never resizes), headroom sized for the largest accessibility category, no text clamped (FR11, NFR8, UX-DR13) — `readingComposition`'s `content` gains a `GeometryReader`/`ScrollView` wrapper (the same pattern `project-context.md`'s Centering Pattern section documents for Home/Tutorial, `Spacer()`-free), and every reading-surface `Text` is bound to a named DESIGN.md typography role (`.bodyStyle()`, a new `.choiceLabelStyle()`, `.echoCallbackStyle()`) instead of an unstyled default. The current content tree only ever authors a 2-option choice node (`StoryTree.swift`'s `.firstChoice`) — verify scrolling against that node plus code-level layout inspection against `mockups/story-choice-three-way.html`'s 3-choice accessibility-size case; do not add a temporary 3rd option to real content to exercise this.

3. **Given** Reduce Motion is enabled
   **When** a choice charges or an echo/interstitial/page transition occurs
   **Then** the charge-fill animation is skipped (instant commit) and frame/interstitial/page-turn transitions collapse to instant cuts — nothing produces continuous or looping motion (NFR5, UX-DR14). This requires two things together, not just gating: (a) real transitions/animations must first exist for the frame's echo power-up and the interstitial's entrance/exit (today both are hard instant swaps with zero `.animation`/`.transition` calls — "correct until Story 2.8 introduces something for Reduce Motion to later govern," per `FrameView.swift:11-13` and `BranchArrivalInterstitialView.swift:20-22`'s own comments), and (b) every one of those new transitions, plus the pre-existing `ChoiceCardView.touchDown()` charge-fill animation, must read `@Environment(\.accessibilityReduceMotion)` and collapse to instant when it's `true`. Neither half alone satisfies this AC.

4. **Given** VoiceOver is active on a Story/Choice page
   **When** focus traversal occurs
   **Then** order follows prose → choices → run-options-last (UX-DR12, scoped per the Scope Decision above — no eyebrow/pager elements exist to include). `RunOptionsButton`'s `.accessibilitySortPriority(-1)` (Story 2.7) already satisfies "run-options last"; verify prose → choices holds by default visual/document order (no `.accessibilitySortPriority` overrides needed there) and confirm in Simulator (AC #5).

5. **Given** this story touches only `Views/` (SwiftUI presentation layer) — no `StoryRunEngine`/`Content` changes, since Reduce Motion is read directly from SwiftUI's environment per-view (AD-3's Engine/Presentation split: Engine never touches rendering/animation) — and this devcontainer cannot render SwiftUI, take a screenshot, or toggle Simulator accessibility settings
   **When** implementation is complete
   **Then** the user is asked to confirm in Xcode/Simulator: (1) colors/typography visually match DESIGN.md/the warm-ink-circuit mockup in both light and dark mode across a reading page, a choice page, the echo-callback block, the branch-arrival interstitial, and the run-options icon; (2) Dynamic Type set to an accessibility category (e.g. AX5) on a reading page and the 2-choice page shows scrolling content under a fixed, non-resizing frame with no clipped text; (3) Reduce Motion enabled in Settings/Simulator shows the choice-card commit path with no visible 3s charge-fill, and the frame/interstitial show no glow/transition/animated cut; (4) Reduce Motion disabled shows the new frame power-up and interstitial entrance/exit transitions actually animating (proving (3) is a real gate, not a no-op with the animation deleted entirely); (5) VoiceOver traversal on a Story/Choice page confirms prose → choices → run-options-last; (6) no regressions in existing gesture/page-turn/choice-commit behavior from Stories 2.2/2.3/2.5/2.6/2.7/2.9. Result + date recorded in the story's Completion Notes List (project-context.md Process Agreement).
