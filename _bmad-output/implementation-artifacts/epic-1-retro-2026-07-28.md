## What Went Well

- **Functional-before-polish sequencing.** Stories 1.2/1.3 built working Home/Tutorial screens with placeholder styling; 1.4 applied the DESIGN.md visual-identity pass afterward. By the time styling changed, navigation wiring, the `RunSnapshotPresence` contract, and the Spacer-free landscape layout were already locked in and tested — 1.4 could stay narrowly scoped to text/color/button modifiers only.
- **Scope discipline held throughout.** Story 1.2 explicitly refused to pre-build any part of `RunSnapshot`/`StoryRunEngine` even though it would have been easy to smuggle in "just a little" engine logic. Later stories repeated this pattern (1.4 refused to touch `RootView.swift`; 1.6 refused to pre-define unused spacing-scale constants).
- **Gaps became dedicated stories, not silent debt.** 1.5 (subtitle) and 1.6 (named constants) both originated from real gaps noticed during code review of a prior story, and were given their own scoped story rather than left as an open TODO.
- **Doc conflicts were resolved and the source docs corrected**, not just patched around in code — DESIGN.md, EXPERIENCE.md, UX-DR1, and the mockups were all updated to match the circuit-frame and headline-case decisions.
- **The devcontainer's static-verification ceiling was raised mid-epic**, not just worked around — a real Swift toolchain (`swiftc`) was added outside of any story (commit `4991bce`), and `project-context.md`'s environment notes were corrected to reflect it precisely (parser-level checks now possible; full builds/Simulator still require the user).
- User feedback: "I learned a lot about Xcode and the capabilities of the bmad-method. I like that we try and prove the path logically, before getting hung up on a polished few screens."

## Challenges

- **Every code review caught the same flavor of miss**: Dynamic Type tracking not scaling (fixed via `@ScaledMetric` in 1.4), missing `.contentShape(Rectangle())` on transparent-background buttons, disabled-state opacity silently dropped when replacing system button styles, and a `LocalizedStringKey` ternary resolving the wrong `Text` overload. These are SwiftUI/accessibility idioms that don't surface on a first implementation pass — mostly invisible to the user until code review flagged them.
- **The no-toolchain devcontainer meant real functional bugs only surfaced via manual Simulator testing**, never from the dev agent's own static checks (brace-balance, JSON validity, grep). The landscape `Spacer()` bug and the cold-launch orientation mismatch were both found this way, not by any automated check.
- **Forward-pointing warnings for future epics initially had only one weak surface.** The `.id(layoutGeneration)` state-loss risk for Epic 2's reading surface existed only in `deferred-work.md`, which is not an automatically-loaded input to `bmad-create-story` — relying on it alone would have meant relying on someone remembering to check.

## Key Insights

1. Rules learned via code review need an *active* checkpoint, not just documentation to read once at story start. `project-context.md` already captured the four recurring SwiftUI/accessibility gotchas as prose; this retro converted them into a literal checklist (Pre-Completion Self-Check) to be re-run right before a story leaves for review.
2. Not every forward-pointing risk note is equally durable. A source-code comment only surfaces if the next implementer happens to open that exact file. `project-context.md` (loaded unconditionally on every story) and the relevant epic's own `epics.md` entry (loaded whenever that story is created) are the reliable channels — comments are a useful third layer, not a sufficient one on their own.
3. Cross-story contracts work best when they're embedded in the code itself, not just prose. The `RunSnapshot` `UserDefaults` key (`com.forkedechoes.runSnapshot`) is safe because whoever implements Story 2.4 has to open `RunSnapshotPresence.swift` to do the work at all — the warning is unavoidable. The `layoutGeneration` risk didn't have that property and needed to be deliberately reinforced across three surfaces instead.
