- (decision) Story tree is authored as external JSON, bundled at build time (not app-code Swift literals). Binds: content model, story engine. Prevents: coupling story authoring to Swift recompilation. Trade-off surfaced: loses compiler-level referential-integrity checking (unreachable branches, dangling echo/choice references) that Swift structs would give for free — needs a deliberate validation strategy.
- (decision) Story content split: structure (node/choice IDs, choice targets, ending kind, alignment deltas, echo wiring) lives in Swift indirect enum literals — compiler enforces every branch terminates in exactly one ending (FR-8) and catches dangling references at build time. Prose (body text, choice labels, echo callback text, tutorial/ending copy, VoiceOver labels) lives in an Xcode String Catalog (.xcstrings), referenced by stable keys via LocalizedStringResource. Binds: content model, story engine, localization. Prevents: coupling localization to tree structure; loses no compile-time safety on references (Xcode 26 can generate type-safe symbols for manually-managed catalog keys).
- (version) String Catalog (.xcstrings) default since Xcode 15 (2023), enhanced in Xcode 26 (2026) with type-safe symbol generation. LocalizedStringResource requires iOS 16+ — well within PRD's N/N-1 support window. Verified via web search 2026-07-25.
- (decision) State management: MVVM with @Observable (Apple's 2026 default), but as ONE shared run-engine object (StoryRunEngine) rather than per-screen ViewModels. Binds: Home, Tutorial, Story/Choice, Ending, Memory screens; run state (current node, choice history, alignment score). Prevents: run state fragmenting across multiple ViewModels that must stay in sync; screens mutating state directly instead of through defined intents. Rule: engine is sole owner/mutator of run state, exposed only via intent methods (selectChoice, advancePage, etc.); screens hold only local/transient UI state (e.g. charge-animation progress) via plain @State, injected via @Environment.
- (decision) Run persistence: engine's run state (current node ID, ordered choice history, alignment score, tutorial-seen flag) modeled as a single Codable RunSnapshot, JSON-encoded and stored under one UserDefaults key. Binds: StoryRunEngine, Home resume/Restart, Run-options action sheet. Prevents: over-engineering persistence with FileManager/Core Data/SwiftData for a state blob this small. Rule: engine writes snapshot on mutation or scene-phase background transition; decodes on cold launch to restore in-progress run; Restart This Run clears the key.
- (decision) Story pager: single reading-surface view; StoryRunEngine owns 'what is currently displayed' as an enum/pointer into the content tree (reading node / branch-arrival interstitial / ending / memory). Swipe gestures and invisible tap zones call engine intents (advancePage/goBack); engine decides if forward nav is allowed (blocks on unresolved choice, FR-3) and whether to show a revisited choice locked (FR-5). View transitions content via .transition/.animation in response to engine state, not a native pager container. NavigationStack (if used at all) reserved for the coarse top-level flow (Home/Tutorial/Story session/Ending/Memory), never per-story-page. Binds: navigation, StoryRunEngine, Story/Choice view. Prevents: forcing tree-shaped, choice-gated content into NavigationStack push/pop or TabView(.page), both of which assume a fixed known page list and have no clean hook to block forward navigation on an external condition.
- (version) Stack verified 2026-07-25: Swift 6.3, iOS 26 SDK / iOS 18 minimum deployment target (N/N-1 per PRD), Xcode 26.6, SwiftUI, Swift Testing (macro-based, Xcode 16+) for unit tests. XCTest still supported, used only if UI automation is added later (not required by PRD).
- (decision) Testing convention: Swift Testing covers StoryRunEngine logic — alignment-tier resolution, echo-firing timing, hard-fail bypass, persistence round-trip (RunSnapshot encode/decode). Binds: StoryRunEngine, ending resolution, persistence. Prevents: untested tier-boundary regressions (addendum.md's Home 1-2/Stay 3-4/else-Limbo bands already had one overlap bug caught by hand; a boundary test suite catches the next one). No automated UI-test requirement beyond FR-11 manual/VoiceOver playtesting.
- (decision) Ending resolution: single pure function scoreToEnding(score) -> EndingKind is the one place alignment-tier thresholds (Home 1-2, Stay 3-4, else Limbo) live; hard-fail bypasses this function entirely via a direct engine transition from a designated gotcha choice (FR-8). Binds: StoryRunEngine, content model (choice alignment deltas), addendum.md thresholds. Prevents: tier thresholds being duplicated or drifting between content authoring and engine code.
- (decision) Illustrations: bundled in Assets.xcassets, one image set per branch-reality flavor (~10-15), referenced via Xcode-generated type-safe ImageResource symbols (not raw string names) so a dangling illustration reference is also a compile error. Binds: content model, branch-arrival interstitial, FR-12. Prevents: runtime-only failure mode for a missing/misnamed bundled asset.
- (decision) Deployment/operational envelope: single Xcode app target, Debug/Release configs only, no backend/server/infra of any kind (on-device only, per PRD platform constraint). Distribution via App Store Connect; TestFlight for solo/friends playtesting pre-submission. Requires Apple Developer Program enrollment before any TestFlight or App Store submission (PRD Open Question 5, still unresolved — flagged as blocking prerequisite, not an architecture decision this spine can close).

Closes adversarial finding: two builds of FR-6 echo-wiring diverging on structural-vs-conditional firing.
- (decision) Reviewer-gate fix: AD-3 tightened — full named intent surface (selectChoice/advancePage/goBack/exitToHome/restartRun/startNewRun), advancePage() reused as the generic 'continue past blocking beat' intent for Interstitial and Ending. Choice commit timing pinned: press-and-hold charge and tap-then-1.5s-undo-window are View-local transient state; selectChoice(_:) fires exactly once at finalization, never eagerly/revocably — resolves the force-quit-mid-undo-window ambiguity (nothing was committed, relaunch shows the page undecided). Rendering projection gains an isEcho field so views know to power up the frame. Closes rubric/adversarial findings on unpinned commit semantics and missing intents.
- (decision) Reviewer-gate fix: AD-4 tightened — RunSnapshot/ChoiceRecord fields defined concretely (IDs only, never frozen prose, per AD-2). Writes are synchronous/immediate (never debounced) — no in-progress page can be lost to abrupt termination. Decode failure treated as 'no snapshot' (fresh-run fallback, no crash). Snapshot cleared on reaching Ending and on restartRun/startNewRun — a completed run never mistakenly offers 'Resume Story'. Closes adversarial findings on ChoiceRecord shape, write-trigger ambiguity, and dead-snapshot-resume bug.
