Many-Worlds CYOA — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-game-2026-07-25/

The spine pair is close to source-extractable: token definitions are complete and resolve cleanly, section order matches the canonical shape, and both Key Flows mirror the PRD's UJ-1/UJ-2 verbatim with named protagonist, numbered steps, and a clear climax. One critical defect breaks the "source-extract cleanly" bar outright — EXPERIENCE.md's Information Architecture section falsely claims four of the five IA surfaces have no visual mockup when all five exist and DESIGN.md already links them — plus two high-severity gaps (no stated contrast targets despite a hard FR-11 requirement, and no DESIGN.md spec at all for the Memory screen's score/tier display).

The accessibility lens raises the stakes further: page-turn navigation is documented as swipe-only with no tap/VoiceOver equivalent anywhere — a direct contradiction of FR-11's hard "no gesture-only interaction" constraint, and a real iOS mechanics problem since VoiceOver consumes one-finger swipes for its own navigation. The echo-callback tag — the label for the app's signature "story remembers" moment, firing 2-3 times every run — also fails WCAG AA contrast in both light and dark themes. Combined, this is one more targeted edit pass, not a redesign, before the pair is safe to build from.

Accessibility review

review-accessibility.md

Not build-ready as-is. The spine gets the headline gesture story mostly right (hold-to-confirm with an explicit, repeated tap equivalent, and a correct VoiceOver double-tap mapping), but it has one direct, provable contradiction of FR-11's hard constraint, one clear WCAG AA contrast failure on a core recurring component in both color schemes, and an asymmetric-safety-net bug in the tap-commit path that specifically disadvantages the motor-impaired/VoiceOver users it claims to serve. Fixable with spec edits, not a redesign — but needs another pass before an engineer should start building against this pair.

Critical

Swipe-driven page turn has no tap/VoiceOver equivalent

EXPERIENCE.md, Interaction Primitives + Component Patterns "Story page"
FR-11 is explicit: no interaction reachable only via a custom gesture. Page-turning is the single most frequent interaction in the app and, as documented, is swipe-only — and a real iOS mechanics problem, since VoiceOver consumes one-finger swipes for its own navigation unless an alternate path is built. Every other gesture in the system got an explicit equivalent; page turn did not.
Fix: add a tap-accessible page-turn affordance (edge tap zones, or a VoiceOver custom rotor action "Next/Previous page") and document it in both Component Patterns and the Accessibility Floor.
High

Tap-to-commit is instant/irrevocable while hold allows cancel-by-release

EXPERIENCE.md, Component Patterns "Choice card"; State Patterns
A user relying on tap — tremor, limited dexterity, or a VoiceOver double-tap used to explore rather than commit — gets zero opportunity to reconsider before a choice locks permanently (FR-5), while the "primary" hold gesture has a built-in grace period. The path meant to be more accessible is less forgiving than the gestural one.
Fix: add a brief confirm/undo step after a quick tap, or explicitly document why instant-lock-on-tap is intentional and reconsider how VoiceOver's double-tap should route.
High

echo-callback tag fails WCAG AA contrast in both themes

DESIGN.md components.echo-callback; mockup CSS .echo-tag
Computed: light mode #C2540F on #241C14 ≈ 3.65:1; dark mode #E0763A on #F3ECDD ≈ 2.62:1 — both below the 4.5:1 required for small bold/uppercase text. This is the label for the app's signature callback moment, appearing 2-3 times every run.
Fix: introduce a separate text-safe ember token for this role, or move the tag text to ink-on-inverse and reserve ember for a small icon/underline accent.
Medium

trace-brass and ember are near-identical in luminance

DESIGN.md colors.trace-brass / colors.accent-ember
Computed relative luminance: #8B6F47 ≈ 0.173 vs. #C2540F ≈ 0.178 — indistinguishable by lightness alone; orange/brown is a classic CVD confusion pair. Functional meaning isn't lost (text co-fires with the frame), but the app's own stated signature device is silently non-functional as a standalone signal for colorblind users.
Fix: state this explicitly as an accepted, redundantly-backed limitation, or add a non-hue cue (dash pattern, filled-vs-hollow via, larger brightness jump).
Medium

Fixed-pixel circuit-corner geometry risks collisions at accessibility Dynamic Type sizes

mockup CSS; DESIGN.md Shapes/Components
Fixed 30×30px corner assemblies and fixed frame-well padding don't scale with enlarged text; the interstitial's unclamped headline is layered over position-fixed decorative art with no reflow relationship.
Fix: specify that frame-well padding/corner clearance scale with the largest supported Dynamic Type category, and state how the interstitial's art responds when its headline wraps.
Medium

No mapping from typography roles to iOS Dynamic Type text styles

DESIGN.md, Typography
Literal pixel values are given per role with "must scale" instructions, but no UIFontTextStyle binding — two implementations could scale roles at inconsistent relative rates, breaking the weight/scale hierarchy Brand & Style calls load-bearing.
Fix: add an explicit token-to-text-style mapping table (headline → .title1-scaled, body/echo-callback → .body, choice-label → .headline, eyebrow/meta → .caption2).
Medium

Reduce Motion guidance covers only 2 of the plausible animated moments

EXPERIENCE.md, Accessibility Floor
Page-turn transition and the interstitial's entrance/exit are unaddressed, in tension with DESIGN.md's blanket claim that the echo glow is "the only thing in this system allowed to animate."
Fix: state explicitly whether page turns and the interstitial transition animate under normal conditions, and what they collapse to under Reduce Motion.
Low

Run-options button has no specified accessibilityLabel

EXPERIENCE.md, Accessibility Floor — absence
A default SF Symbol VoiceOver name may not clearly convey "opens exit/restart options" to a blind user.
Fix: add "Run options" as the explicit accessibilityLabel.
Low

ink-secondary on surface-base passes AA only marginally

DESIGN.md colors
~4.85:1 against the 4.5:1 minimum, used for pager/meta/caption roles — close enough that implementation drift could tip it under the line.
Fix: darken slightly for margin, or confirm this pairing is only used at caption-level (17px), not the smaller 12px meta/pager role.
Low

No stated position on iOS "Bold Text"/"Increase Contrast" interaction

DESIGN.md, Typography — absence
The hierarchy comes specifically from weight contrast (900 vs 500 vs 800); Bold Text could flatten that relationship system-wide.
Fix: note whether the type system is expected to remain legible under Bold Text, or accept as an unhandled edge case.

EXPERIENCE.md instead cites DESIGN.md via backtick dotted-paths (e.g. DESIGN.md.components.frame); every one resolves to a real DESIGN.md section or component — a different but internally consistent convention, not a defect.
