- (capability) CAP-1 (FR-1 Home screen entry): intent player chooses Start Story or Start Tutorial from home, each a distinct gesture + accessible tap equivalent; success both entries reachable via VoiceOver/standard tap, title shown.
- (capability) CAP-2 (FR-2 Tutorial screen): intent player views a tutorial explaining mechanics then returns home or starts story; success tutorial reachable only from home, both exits gesture+tap accessible.
- (capability) CAP-3 (FR-3 Page navigation): intent player advances/returns within a branch via swipe + accessible equivalent; success forward blocked on unresolved choice page, backward always available once >=1 page read.
- (capability) CAP-4 (FR-4 Choice presentation & selection): intent player selects one of the presented choices, each distinct gesture + accessible tap/VoiceOver equivalent; success choice page offers >=2 independently selectable choices, selecting unblocks forward nav.
- (capability) CAP-5 (FR-5 Choice permanence): intent a made choice cannot be changed by re-navigating to that page; success revisiting a decided choice page shows the made choice with no alternate-choice control.
- (capability) CAP-6 (FR-6 Narrative callback/echo): intent story text explicitly references an earlier choice's consequence 2-3 times later in the run; success each echo's callback text is distinguishable in-prose as referencing that earlier decision.
- (capability) CAP-7 (FR-7 Silent alignment scoring): intent each choice carries an author-assigned +/- alignment value summed silently during play; success no alignment value or running total is ever visible to the player during a run.
- (capability) CAP-8 (FR-8 Ending resolution): intent at branch end the run resolves to home/stay/limbo (by score/tier) or hard-fail (gotcha choice, bypassing scoring); success every branch terminates in exactly one of the four ending types, hard-fail reachable only via a designated gotcha choice.
- (capability) CAP-9 (FR-9 Ending screen): intent the system displays an ending screen via one shared template across all four ending types with outcome-specific text; success all four types render through the same screen component, differing only in text.
- (capability) CAP-10 (FR-10 End-of-run recap/Memory): intent after the ending screen the system shows a memory screen listing choices made, what each caused, and score/tier, for every ending incl. hard-fail; success memory screen shown for 100% of completed runs, player can return home or start a new run from it.
- (capability) CAP-11 (FR-11 Accessible interaction parity): intent every gesture-based interaction has a standard VoiceOver-compatible tap alternative, story text follows Apple HIG accessibility guidance; success no interaction reachable only via custom gesture, story text area passes VoiceOver nav and Dynamic Type.
- (capability) CAP-12 (FR-12 Bundled illustrations): intent app ships one pre-generated illustration per distinct branch-reality flavor (~10-15), bundled in the binary; success no illustration is fetched over the network at runtime.
- (constraint) On-device only: no network calls, backend, or external integrations (product-level privacy/scope constraint, not just an implementation choice); support current major iOS release and N-1.
- (constraint) Alignment score maps to ending tier: Home 1-2, Stay 3-4, Limbo otherwise; hard-fail bypasses scoring entirely via a designated gotcha choice (addendum.md, boundary-fixed 2026-07-25 to close the Home/Stay overlap at score 2).
- (constraint) Story tree must always contain an ideal path leading home, even if not obvious to the player while choosing (authoring north star for whoever writes the content tree).
- (constraint) Safe-looking choices must not always guarantee the safe outcome (narrative pushback so players aren't trained to blind-pick 'safest'); no spendable resource backs this in v1.
- (non-goal) Not a business: no revenue goal. A possible $0.99 App Store price, if the app feels like a finished real thing, is a marker not a monetization strategy — pricing is conditional, not committed.

- (non-goal) Second-language translation is not a v1 commitment (the String Catalog seam exists but shipping another language does not); iPad/Universal support is not designed for in v1 (iPhone-only, portrait, single-column reading surface).
